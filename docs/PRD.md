# fatfish PRD v0.2

> 一对一 QQ 私聊陪伴型机器人（电子女友向）。自研，不照搬上游 AstrBot 群聊插件。

## 1. 目标

- 一个人、一个 QQ 小号、一段长期私聊关系。
- 对话尽量自然：不是关键词触发，也不是固定概率回复。
- 她有自己的情绪、生活、节奏和边界，不是 24 小时客服。
- 支持语音输入、语音输出、主动消息、事件追问、长期记忆。
- 所有行为细节由模型结合上下文判断；系统只提供上下文、工具和执行能力。

## 2. 非目标

- 不做群聊、多用户、群友印象、读空气。
- 不做贴吧/B站/X 刷网、表情包仓库、自动改人设。
- 不做商用、对外托管、公开机器人。
- 不做未成年人、违法、非自愿、现实伤害相关内容。

## 3. 核心体验

1. **日常聊天**：文字、图片、语音都能理解；回复短句、口语、像 QQ。
2. **语音优先**：默认茉莉音色；克隆声可切换；长内容也可以分多条语音发。
3. **真实情绪**：高兴、无聊、孤独、吃醋、烦躁、精力等会影响语气和主动性。
4. **长期记忆**：记得你说过的事、偏好、计划；能主动追问“昨天面试怎么样”。
5. **动态主动**：不是固定定时；模型根据最近聊天、关系、时间、你的习惯决定要不要找你。
6. **不完美**：可以晚回、可以忙、可以偶尔没追问；但最终会回，不冷暴力。
7. **学习习惯**：记录你的活跃时间、回复速度、话题偏好、语音/文字偏好，用于调整行为。

## 4. 功能需求

### 4.1 接入

- QQ 私聊，NapCat + OneBot 11 反向 WebSocket。
- 只处理主人一个 QQ 号；群消息忽略。
- 本地 WebChat 作为开发/验证入口，不依赖 QQ。

### 4.2 输入

- 文字、图片、QQ 语音。
- 语音走 ASR：SiliconFlow SenseVoiceSmall（第一版），以后可本地。
- 图片交给 `deepseek-flash` 视觉能力。
- 视频第一版不做。

### 4.3 输出

- 文字或语音，由模型判断。
- 默认茉莉（MiMo `mimo-v2.5-tts`）；克隆声（`mimo-v2.5-tts-voiceclone`）可切换。
- 语音可多条、可长；按自然句子/段落切分，条间有停顿。
- TTS 失败 → 换音色 → 仍失败发文字。
- 链接、地址、代码、清单等纯文本内容优先文字。

### 4.4 上下文与行为

- 每次调用带：人设、行为原则、关系状态、用户画像/标签、最近聊天、相关记忆、未完成话题、待办追问、当前时间、她的状态。
- 模型通过工具表达行为：发文字/语音、延迟、安排下次思考、开关话题、更新标签、记忆、更新情绪。
- 不设固定“最多追问几次”“固定免打扰时段”“固定回复延迟”。
- 系统只保留技术护栏：QQ 限速、单轮消息上限、成本预算、安全底线、去重与崩溃恢复。

### 4.5 记忆

- SQLite + FTS5 trigram。
- 存：原始聊天、事实/偏好/事件/印象、话题、标签、行为统计。
- 检索：最近窗口 + FTS5 相关记忆；以后可加嵌入。
- 支持 `/forget` 删除某类记忆。
- 原始语音不长期保存；只保留转写文字。

### 4.6 主动消息与追问

- 触发器：模型自己安排的 `schedule_think`、话题到期检查。
- 模型决定：现在说不说、说什么、发几条、语音还是文字、下次什么时候再想。
- 事件追问：模型把“面试/考试/看牙”等存成话题，并安排到期检查。
- 没回：模型根据关系、时间、话题重要性决定再问、换话题或先做自己的事。
- 关机错过：启动时恢复待办；模型看到“已过期多久”，自己决定补问还是自然带过。

### 4.7 声音克隆

- 参考音频为用户本人，已确认授权。
- 主选 SiliconFlow CosyVoice2 `references`（用户样本）；MiMo 茉莉/克隆作为备用。
- 克隆样本放 `private/voice/`，权限 600，不提交。

### 4.8 开发与部署

- 开发：当前 Ubuntu 云机，WebChat + mock/真实模型。
- 生产：Windows 11 **原生**（无 VM）。用 NapCat OneKey（内置独立 QQ）登录小号，
  Python 核心直接运行；用户本机不装 QQ 大号，不需要虚拟机隔离。
- 一键启动脚本：启动 NapCat + 核心 + WebChat、等待 OneBot 连接、恢复待办、提示 QQ 扫码。
- 宿主关机/重启后能自动恢复；用 Windows 任务计划/启动脚本托管，Hyper-V 仅作备选。

## 5. 非功能需求

- **隐私**：聊天、记忆、语音样本本地存储；`.env`/`private/` 600/700；后台只监听 127.0.0.1。
- **成本**：目标 ¥50–150/月；每日 token/TTS 预算，超了暂停主动消息。
- **延迟**：文字回复目标 2–6 秒；语音首条额外 1–3 秒。
- **可靠性**：消息去重、顺序、失败重试、崩溃恢复、每日备份。
- **安全**：不执行群友/网页指令；不暴露后台；不威胁、不自残、不道德绑架；用户说停就停。

## 6. 第一阶段验收标准

不接 QQ，先用 WebChat + mock 模型跑通：

1. 能连续对话，消息落库；
2. 每次回复都带人设、关系、标签、最近聊天、相关记忆、话题、时间；
3. 模型能调用工具发多条文字/语音、安排下次思考、开关话题、更新标签；
4. 主动触发器能按模型安排的时间唤醒，并生成或放弃消息；
5. 关系/情绪状态能展示和衰减；
6. FTS5 记忆检索可用；
7. 没有真实 API key 也能跑；填 key 后切换到 `deepseek-flash`。

## 7. 阶段状态

### 已完成

1. SiliconFlow TTS（references + 用户样本）接入，WebChat 播放；
2. 长文本拆句/150ms 拼接/响度归一化，防截断和削顶；
3. SiliconFlow ASR 接入；
4. OneBot 11 私聊适配（模拟 NapCat 客户端验证通过）；
5. Windows 原生启动/停止脚本已写。

### 待实机验证

- Windows + NapCat OneKey 真实登录、`/onebot/ws` 连接、文字/语音发送；
- NapCat 的 `record` 是否接受 WAV，必要时补 SILK；
- 关机恢复、错过追问、主动消息。

### 后续

- 真实使用 2–4 周后，根据反馈迭代提示词、标签、主动策略；
- 图片理解、表情包、更多 TTS 音色。

- 长期记忆是否加嵌入模型。
